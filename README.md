## 인증 구현 설명서

### 1. 무엇으로 만들었나
- 방식: **WebAuthn 패스키**. 비밀번호 입력칸이 없습니다.
- 라이브러리: **@simplewebauthn/server 14.0.3**(서버, 서명 검증), **@simplewebauthn/browser 14.0.0**(브라우저, 패스키 창 호출).
- 저장소: **Firebase Firestore**(서버만 서비스 계정 키로 접근). 배포: **Vercel**(같은 주소에서 화면과 `/api`를 함께 제공).
- 서명 검증 같은 암호 부분은 직접 짜지 않고 검증된 라이브러리에 맡겼습니다. 제가 짠 부분은 챌린지 1회용 처리, 세션, 계정 분리, 거부 규칙입니다.

### 2. 등록 흐름 (소스를 따라가기)
`public/private.js`의 `register()` → `POST /api/register/options` → `server/auth.js` `registerOptions()` → 기기에서 패스키 생성 → `POST /api/register/verify` → `registerVerify()` → `db.createAccount()`

1. `registerOptions()`가 라이브러리로 **새 무작위 챌린지**를 만들고, 1회용으로 DB에 5분간 보관합니다(요청마다 다름).
2. 브라우저가 기기 안에서 **공개 키/개인 키 한 쌍**을 만듭니다. 개인 키는 기기 밖으로 나오지 않습니다.
3. `registerVerify()`가 챌린지를 **꺼내면서 삭제**(두 번 못 씀)하고, 출처·도메인·서명을 검증한 뒤 **공개 키만** `passkeys` 컬렉션에 저장합니다.
4. 사용자가 중간에 취소하면 `verify`가 호출되지 않으므로 서버에는 아무것도 저장되지 않습니다(계정도 검증 성공 후에만 생성).
- **공개 키는 비밀번호가 아닙니다.** 서명이 맞는지 확인하는 용도라서, 유출돼도 그것만으로 로그인할 수 없습니다.
- 패스키 이름은 사용자가 정합니다(예: "내 휴대폰"). 개인 키는 이 기기의 보안 칩·비밀번호 관리자에 있고, 서버에는 공개 키·이름·만든 날·마지막 사용일·사용 횟수만 있습니다.

### 3. 로그인·로그아웃·세션
`private.js` `login()` → `loginOptions()` → 기기 서명 → `loginVerify()` → `startSession()`

1. `loginOptions()`: 새 챌린지 발급(아이디를 묻지 않음 — 기기가 어떤 패스키인지 알려 줌).
2. `loginVerify()`: ① 챌린지를 꺼내며 삭제(재사용·만료·가짜면 거부) ② 패스키 id로 공개 키 조회(지운 패스키면 거부) ③ `verifyAuthenticationResponse()`로 서명·출처·도메인·사용자 확인 검증 ④ 성공하면 `startSession()`.
3. `startSession()`: 무작위 토큰 발급 → **해시만** DB(`sessions`)에 저장, 원문은 쿠키로만(`HttpOnly`, `SameSite=Strict`, https에서는 `Secure`·`__Host-` 접두사). 로그인할 때마다 토큰을 새로 만듭니다.
4. 로그아웃(`logout()`): 서버에서 세션 문서를 **삭제**합니다. 예전 쿠키를 다시 보내도 401입니다.
5. 성공·실패는 DB(`events`)와 서버 로그에 남습니다. 로그에는 토큰을 앞 4글자 + `****`로만 남깁니다.
6. 패스키를 지우면 그 패스키로 만든 로그인 상태도 함께 끊습니다.

### 4. 공개 / 비공개 나누기, 계정 분리
- **공개**: `public/`의 소개 페이지. 소스에는 비공개 내용이 없고, 비공개 메모는 로그인 후 `/api/notes`로만 내려옵니다(받은 글은 `textContent`로만 표시).
- **비공개**(계정마다 3개 이상): 비공개 메모 목록, 내 패스키 목록, 검증 기록.
- **401**: 모든 비공개 함수는 `requireSession()`으로 시작합니다. 쿠키가 없거나 가짜면 401.
- **계정 구분은 세션으로만**: 주소(`?accountId=`)나 본문(`accountId`)에 적힌 계정은 읽지 않고 무시합니다.
- **403(남의 자료)**: `server/private.js`의 `ownedBy()`가 "이 자료의 주인이 내 세션 계정인가"를 확인하고 아니면 403을 냅니다. 없는 id도 같은 403이라 존재 여부를 알려주지 않습니다. 거부하면 `access_denied` 기록이 남습니다.
- 계정은 최대 2개(`MAX_ACCOUNTS`), 계정당 패스키 최대 5개. **마지막 패스키는 삭제 거부(409)** — 지우면 그 계정으로 못 들어오기 때문입니다.

### 5. 확인한 것 4가지 (성공 요청 + 거부 요청)
아래는 **내 컴퓨터에서 가상 패스키로** 돌린 결과(`npm test`, 49/49 통과)입니다. 배포 후 같은 확인을 진짜 주소와 진짜 휴대폰으로 다시 하고, 값을 그 결과로 바꿔 적습니다. (화면의 "직접 확인해 보기" 버튼으로 할 수 있습니다.)

| # | 확인 | 성공 요청 | 거부 요청 |
|---|---|---|---|
| 1 | 로그인 없이 비공개 접근 | 로그인 후 `GET /api/notes` → 200 | 쿠키 없이 `GET /api/notes` → **401** (가짜 쿠키도 401) |
| 2 | 챌린지 1회용 | 새 챌린지로 로그인 → 성공 | 같은 서명 본문을 다시 전송 → **401** (만료된 챌린지도 401) |
| 3 | 로그아웃이 진짜로 끊는가 | 로그아웃 전 쿠키로 `GET /api/notes` → 200 | 로그아웃 뒤 **같은 쿠키** → **401** |
| 4 | 계정 간 분리 | 내 메모 `GET /api/notes` → 200 | B로 A의 메모 보기·삭제, A의 패스키 삭제 → **403 ×3**, A의 메모 3→3개·패스키 1→1개(그대로). 반대 방향(A→B)도 403 |

그 밖에 확인: 주소·본문에 다른 계정을 적어도 무시, 패스키 2개 등록 후 하나 삭제해도 남은 것으로 로그인, 지운 패스키로는 거부, 등록 취소 시 저장 없음, 세 번째 계정 거부, 다른 출처의 POST 거부(403).

### 6. 아직 못 막은 것 (솔직하게)
- **시도 횟수 제한이 없습니다.** 누군가 로그인/등록 API를 계속 두드려도 서버가 막지 않습니다. Vercel은 요청마다 서버가 따로 떠서 메모리로는 셀 수 없어, 제대로 하려면 DB나 Vercel 방화벽 설정이 필요합니다.
- **분실 복구 수단이 없습니다.** 모든 기기를 잃고 패스키가 하나도 없으면 그 계정에 들어갈 방법이 없습니다(Firestore 콘솔에서 사람이 직접 고쳐야 함).
- **계정 자리 2개를 아무나 먼저 차지할 수 있습니다.** 초대 코드(`INVITE_CODE`)로 막지만, 코드를 설정하지 않으면 열려 있습니다.
- 사용 횟수(카운터)가 항상 0인 패스키(iCloud·구글 비밀번호 관리자)는 복제 탐지를 못 합니다. 일부러 막지 않았습니다.
- 기록(`events`)이 계속 쌓이고 지우는 기능이 없습니다.
- 진짜 Firestore·Vercel·휴대폰으로 하는 확인은 배포 후 직접 해야 합니다(자동 시험은 메모리 DB 기준).

## 배포 순서 (처음 한 번)

1. **Firebase**: 새 프로젝트(예: `aleph-passkey`) → Firestore Database 만들기(프로덕션 모드, 서울) → 프로젝트 설정 → 서비스 계정 → "새 비공개 키 생성"(JSON 파일). **이 JSON은 GitHub에 올리지 않습니다.**
2. **GitHub**: 이 폴더를 새 저장소 `about-me-passkey`로 올리기(GitHub Desktop → Commit → Push).
3. **Vercel**: 저장소 Import → Environment Variables에 `FIREBASE_SERVICE_ACCOUNT`(JSON 전체 붙여넣기), `INVITE_CODE`(내가 정한 코드) → Deploy.
4. **접속은 대표 주소로**: `프로젝트이름.vercel.app`. 미리보기 주소(긴 해시가 붙은 것)에서는 패스키가 동작하지 않습니다(패스키는 주소에 묶여 있음). 나중에 도메인을 바꾸면 기존 패스키는 못 씁니다.
5. 패스키 등록은 **내 휴대폰·개인 기기**에서(공용 PC에 개인 패스키를 남기지 마세요).

내 컴퓨터에서 먼저 보고 싶다면: `npm install` → `npm run dev` → `http://localhost:3000` (메모리 DB라 끄면 사라짐).
