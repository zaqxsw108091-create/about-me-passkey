# 윤대영 소개 — 나만 들어가기 (패스키)

SKT 알레프 과제 8. **과제 1에서 만든 소개 페이지를 그대로 쓰고, 그 맨 아래에** 비밀번호 없는 비공개 자리("나만 들어가기")를 붙였습니다.

- 공개 결과물: https://about-me-passkey.vercel.app/
- 소스(커밋 고정): https://github.com/zaqxsw108091-create/about-me-passkey/tree/3bdc33aea1c5ddde4942e311bf5bee982d29ed5b
  - 위 커밋은 코드가 끝난 시점입니다. 이 README는 그 뒤 커밋에서 고쳤고, 코드는 바뀌지 않았습니다.

## 만들어 넣은 내용입니다 (실제 개인정보 아님)

- "나만 들어가기"의 계정 이름 `누리영A`, `누리영B`는 별명입니다. 비공개 메모·패스키 이름(`휴대폰B` 등)은 모두 **만들어 넣은 예시**이고, 실제 연락처·신분증 번호·비밀번호는 없습니다.
- 과제 1 소개 페이지에는 원래 이메일 주소가 있었지만, "실제 연락처를 넣지 않는다"는 조건 때문에 **이 제출용 복사본에서만 뺐습니다.** 나머지 공개 내용(이름, 소개, 만든 프로젝트, GitHub 링크)은 과제 1 그대로입니다.
- 이전 커밋 기록에는 이메일이 남아 있습니다(과제 1 사이트에 이미 공개돼 있던 주소입니다).

## 인증 구현 설명서

### ① 무엇으로 붙였나
- 방식: **WebAuthn 패스키**. 비밀번호 입력칸이 없습니다.
- **라이브러리를 썼습니다**: `@simplewebauthn/server` 14.0.3(서명 검증), `@simplewebauthn/browser` 14.0.0(패스키 창 호출).
- **인증 서비스는 쓰지 않았습니다.** Firebase Authentication, OAuth 같은 로그인 서비스는 쓰지 않았고, Firebase는 **Firestore(DB)만** 씁니다. 배포는 Vercel(화면과 `/api`를 같은 주소에서 제공).
- **직접 구현한 것**: 챌린지 1회용 보관·삭제, 세션(토큰 해시 저장), 계정 분리 검사(`ownedBy`), 거부 코드·기록.

### ② 왜 그걸 골랐나
- 서명 검증 같은 암호 부분은 직접 짜면 틀리기 쉬워서, 검증된 라이브러리에 맡겼습니다.
- 로그인 서비스를 쓰면 "어디서 무엇을 거부하는지"를 내 눈으로 확인할 수 없습니다. 이 과제는 **거부가 소스 어디서 나는지** 보여 주는 것이 핵심이라, 흐름은 직접 짰습니다.
- DB는 새 Firebase 프로젝트의 Firestore입니다. 프로덕션 모드 규칙(`firestore.rules`)으로 브라우저의 직접 접근을 전부 막고, 서버만 서비스 계정 키로 접근합니다.

### ③ 어디를 어떻게 고쳤나 (네 가지 흐름이 소스의 어디를 지나는지)
1. **등록**: `public/private.js` `register()` → `POST /api/register/options` → `server/auth.js` `registerOptions()`(새 챌린지 발급, 5분, 1회용) → 기기가 공개 키/개인 키 한 쌍을 만듦 → `POST /api/register/verify` → `registerVerify()`가 챌린지를 **꺼내면서 삭제**(`takeValidChallenge`, auth.js 86줄)하고 서명을 검증한 뒤 **공개 키만** `passkeys` 컬렉션에 저장 → `startSession()`.
2. **로그인**: `private.js` `login()` → `loginOptions()`(새 챌린지) → 기기 서명 → `loginVerify()`: 챌린지를 꺼내며 삭제(재사용·만료면 거부) → 패스키 id로 공개 키 조회(지운 패스키면 거부) → `verifyAuthenticationResponse()` → `startSession()`. 세션 토큰은 **해시만** DB에 저장하고, 원문은 쿠키(`HttpOnly`, `SameSite=Strict`, https에서는 `Secure`·`__Host-`)로만 갑니다. 로그인할 때마다 토큰을 새로 만듭니다(유지 12시간).
3. **로그아웃**: `private.js` `logout()` → `POST /api/logout` → `server/auth.js` `logout()`이 세션 문서를 **DB에서 삭제**하고 쿠키를 지웁니다. 지운 뒤에는 같은 쿠키 값이 와도 401입니다.
4. **비공개 자료 조회**: `private.js` `loadNotes()` → `GET /api/notes` → `server/private.js` `listNotes()` → 첫 줄 `requireSession()`(없으면 **401**) → 계정은 **세션에서만** 정해 `db.listNotes(accountId)`. 메모 한 건을 요청하면 `getNote()` → **`ownedBy()`(server/private.js 9줄)** 가 "이 자료의 주인이 내 세션 계정인가"를 보고 아니면 **403 NOT_YOURS**를 냅니다. 메모 삭제(56줄)·패스키 삭제(74줄)도 같은 `ownedBy()`를 지납니다. 주소(`?accountId=`)나 본문(`accountId`)에 적힌 계정은 읽지 않고 무시합니다.

**거부를 만드는 소스 위치**
- 로그인 없음 → 401: `server/auth.js` `requireSession()` (59줄)
- 남의 자료 → 403: `server/private.js` `ownedBy()` (9줄)
- 쓴 챌린지 재사용 → 401: `server/auth.js` `takeValidChallenge()` (86줄) → `loginVerify()`
- 지운 패스키 → 401: `loginVerify()`의 `unknown-or-deleted-passkey`
- 마지막 패스키 삭제 → 409: `server/private.js` `deletePasskey()` (`last-passkey`)

### ④ 안 열리는 것을 확인한 기록 (진짜 배포 주소 + 진짜 휴대폰)
`https://about-me-passkey.vercel.app/`에서 휴대폰으로 직접 눌러 본 결과입니다. 화면 아래 "직접 확인해 보기" 버튼으로 서버에 바로 요청하고, 거부 전후 개수를 같이 봅니다.

**1) 로그인 없이 열기**
- 성공: 공개 소개 페이지는 로그인 없이 시크릿 창에서 열림. 로그인한 뒤 `GET /api/notes` → 200, 내 메모가 보임.
- 거부: **쿠키 없이** `GET /api/notes` → **401 LOGIN_REQUIRED · 로그인이 필요합니다.**

**2) 남의 패스키로(=다른 계정으로) 열기**
- 성공: 계정 A로 로그인해 A의 메모 3개 조회. 계정 B로 로그인해 B의 메모 4개 조회.
- 거부 (A로 로그인 → B의 메모 id로): `GET /api/notes/{B의 메모}` → **403 NOT_YOURS**, `DELETE` → **403 NOT_YOURS**. 거부 전후 **내 메모 3개→3개, 내 패스키 1개→1개**.
- 거부 (B로 로그인 → A의 메모·패스키 id로): `GET`·`DELETE` → **403 NOT_YOURS**(내 메모 4개→4개, 패스키 1개→1개). A의 패스키 `KY6KEq…`를 지우려는 `DELETE /api/passkeys/{id}` → **403 NOT_YOURS**, 검증 기록에 `passkey-delete-not-yours`. Firestore `passkeys`에 그 패스키가 그대로 남아 있음.

**3) 이미 쓴 질문(챌린지) 다시 쓰기**
- 성공: 새 챌린지(`oJ41W1XE…`)에 패스키로 서명 → 첫 전송 **200 OK**, 새 세션 발급.
- 거부: **똑같은 서명 본문을 한 번 더** 전송 → **401 LOGIN_FAILED**. 검증 기록에 `challenge-unknown-or-reused`.
- 챌린지는 요청마다 달랐습니다(확인한 값: `915eaTBs…`, `Sl9jUXqV…`, `ThXzJyO6…`, `oJ41W1XE…`, `akRwbniA…` 등).

**4) 패스키를 지운 뒤 로그인**
- 성공: 같은 계정에 패스키 2개(구글 비밀번호 관리자 + 삼성 패스)를 등록 → 하나(`O69ZSQ…`)를 지움 → **남은 패스키(`KY6KEq…`)로 로그인 성공**.
- 거부: **지운 패스키로 로그인 시도** → 로그인 실패(3번). 검증 기록에 `unknown-or-deleted-passkey`. 마지막 하나를 지우려 하면 **409**(`last-passkey`)로 거부.

**곁다리로 확인한 것**
- 로그아웃: 직전 같은 쿠키로 `GET /api/notes` → 200, 로그아웃 뒤 같은 쿠키 값으로 서버가 다시 확인 → **401 LOGIN_REQUIRED**, 브라우저로도 401. (쿠키는 `HttpOnly`라 화면의 JS가 꺼내 다시 보낼 수 없어서, 이 확인은 **서버 안에서 같은 쿠키 값으로 다시 조회**한 것입니다.)
- 저장 내용: Firestore `passkeys` 문서의 필드는 `accountId`, `backedUp`, `counter`, `createdAt`, `deviceType`, `id`, `lastUsedAt`, `name`, `publicKey`, `transports`뿐이고 **개인 키 필드는 없습니다.**
- 개인 키는 휴대폰의 패스키 저장소(구글 비밀번호 관리자, 삼성 패스)에 있습니다.
- 로그인하지 않은 화면에는 비공개 내용이 보이지 않음.

**진짜 배포에서 직접 확인하지 못한 것**
- 로그인하지 않은 채 받은 페이지 소스·응답 본문을 열어 비공개 내용이 없는지는, 자동 시험(가상 패스키)과 소스 저장소 코드로만 확인했습니다.
- 등록 요청 본문에 개인 키가 없다는 것은 자동 시험에서만 확인했고, 진짜 휴대폰의 요청 본문은 열어보지 않았습니다. (저장된 결과는 위처럼 Firestore에서 확인했습니다.)

### ⑤ AI와 나
- **AI에게 맡긴 일**: 서버(등록·로그인·세션·403)·화면·자동 시험(51개)·이 설명서의 초안, 그리고 확인 버튼 두 개(쓴 챌린지 다시 보내기, 로그아웃 뒤 같은 쿠키 확인)를 짜는 일.
- **내가 직접 판단한 일**: 비밀번호 없이 패스키만 쓰기로 하고(계정 2개, 서로 다른 비공개 메모, 새 Firebase 프로젝트), 공용 PC에는 로그인 정보를 남기지 않도록 패스키 등록은 내 휴대폰에서만 했습니다. 배포한 주소에서 ④의 확인(401·403·쿠키 없이 요청·쓴 챌린지 재사용·패스키 삭제 뒤 로그인)을 **내가 진짜 휴대폰으로 하나하나 직접 눌러** 결과가 맞는지 보고 캡처했고, Firestore 콘솔에서 공개 키만 저장됐는지도 직접 봤습니다. AI가 쓴 설명서가 실제 과제 조건과 어긋난다고 지적해 조건 원문으로 다시 맞췄고, 화면에 노출된 서비스 계정 키는 새 키로 바꾸고 옛 키를 지웠습니다.
- **AI 제안을 따르지 않은 일**: AI가 처음 "이메일 줄을 지우자"고 했을 때 이유를 되물었고, AI가 "그대로 두자"로 바꾼 뒤 "조건에 안 어긋나?"라고 다시 물어 조건 원문("실제 연락처를 넣지 않는다")을 확인한 뒤에야 이 제출용 복사본에서만 지웠습니다.

### ⑥ 아직 못 막은 것
- **시도 횟수 제한이 없습니다.** 누군가 로그인·등록 API를 계속 두드려도 서버가 막지 않습니다. Vercel은 요청마다 서버가 따로 떠서 메모리로는 셀 수 없고, 제대로 하려면 DB나 Vercel 방화벽 설정이 필요합니다.
- **분실 복구 수단이 없습니다.** 마지막 패스키는 못 지우게 막았지만, 모든 기기를 잃으면 그 계정에 들어갈 방법이 없습니다(Firestore 콘솔에서 사람이 직접 고쳐야 함).
- **서버에서 지운 패스키가 휴대폰 목록에는 남습니다.** 로그인 창에 지운 패스키(`O69ZSQ…`)가 그대로 떠서 고르면 로그인이 실패했습니다. 서버는 휴대폰 저장소를 지울 수 없습니다.
- **로그인 실패 기록이 계정을 가리지 않고 보입니다.** "누구인지 알 수 없는 시도" 기록은 어떤 계정으로 들어와도 보였습니다(계정 B 화면에서 계정 A가 시도한 실패가 보임).
- **계정 자리 2개를 아무나 먼저 차지할 수 있습니다.** 초대 코드(`INVITE_CODE`)로 막고 있지만, 코드를 설정하지 않으면 열려 있습니다. 이미 계정 2개가 모두 쓰이고 있어 새 계정은 만들 수 없습니다.
- 사용 횟수(`counter`)가 항상 0인 동기화 패스키(구글 비밀번호 관리자 등)는 복제 탐지를 못 합니다. 일부러 막지 않았습니다.
- 기록(`events`)이 계속 쌓이고 지우는 기능이 없습니다.
- 로그아웃 뒤 같은 쿠키 확인은 서버 안에서 한 번 더 조회한 것이라, 밖에서 쿠키를 다시 보내 본 시험은 자동 시험(가상 패스키)에서만 했습니다.

## 짧은 확인 4줄
1. **어디로 가나요**: 새 시크릿 창에서 https://about-me-passkey.vercel.app/ 을 엽니다. 등록·로그인·초대 코드 없이 열립니다.
2. **세 단계 안에 무엇을 하나요**: ① 맨 아래 "나만 들어가기"까지 내려가 비공개 내용이 안 보이는지 봅니다 → ② 주소창에 `https://about-me-passkey.vercel.app/api/notes` 를 열어 봅니다 → ③ 주소 끝에 아무 글자를 붙인 `…/api/notes/abc` 도 열어 봅니다.
3. **무엇이 보이면 통과인가요**: ①에는 "패스키로 들어가기"와 "패스키 만들기" 칸만 있고 메모는 없음. ②③은 메모 대신 `{"error":"LOGIN_REQUIRED","message":"로그인이 필요합니다."}` 가 보임(상태 401).
4. **안 될 때는 무엇이 보이나요**: ②③에 메모 내용이 보이면 실패입니다. 서버 설정 문제일 때는 `SERVER_ERROR`(500)가 보입니다. 패스키 창에서 취소하면 "취소되었거나 시간이 지나 중단되었습니다. 서버에는 아무것도 저장되지 않았습니다."가 보입니다.
   - 로그인한 뒤의 거부(403 NOT_YOURS 등)는 위 ④ 기록에 적었고, 이 사이트는 계정이 이미 2개 모두 쓰이고 있어 심사하는 분이 새로 로그인하지는 못합니다.

## AI와 나 (3줄)
- **AI에게 맡긴 일**: 서버(등록·로그인·세션·403)·화면·자동 시험(51개)·이 설명서의 초안, 확인 버튼 두 개를 짜는 일.
- **내가 직접 판단한 일**: 비밀번호 없이 패스키만 쓰고, 공용 PC에 로그인 정보를 남기지 않도록 등록은 내 휴대폰에서만 했습니다. 배포 주소에서 401·403·쓴 챌린지 재사용·삭제 뒤 로그인을 진짜 휴대폰으로 하나하나 직접 눌러 확인했고, 설명서가 실제 조건과 어긋난다고 지적해 원문으로 다시 맞췄으며, 노출된 서비스 계정 키는 새 키로 바꿨습니다.
- **AI 제안을 따르지 않은 일**: "이메일 줄을 지우자"는 AI 제안에 이유를 되물었고, 조건 원문을 확인한 뒤에야 이 제출용 복사본에서만 지웠습니다.
